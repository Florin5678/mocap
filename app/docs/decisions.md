# Decisions

Design choices made while building (PROJECT.md tag [DECIDE]). Owner decisions D1–D16 live in PROJECT.md §0.1 and are not repeated here.

| Date | Topic | Decision | Why |
|---|---|---|---|
| 2026-11-12 | Python / env | Python 3.12, `uv`, app in `app/` with its own `pyproject.toml`; Pose2Sim installed editable from the fork root (`[tool.uv.sources] pose2sim = { path = "..", editable = true }`); `uv.lock` committed. | Inside OpenSim's supported range (3.11–3.13); one lock file pins everything; upstream files stay untouched. |
| 2026-11-12 | Build backend | hatchling for `mocapapp`. | Simple src-layout packaging; upstream keeps setuptools. |
| 2026-11-12 | How stages are run | One subprocess per stage, `cwd` = trial folder, `Pose2SimPipeline()` called **without** a config argument. | Upstream resolves `session_dir` from the *current directory* when given a path (see upstream-notes §1); running inside the trial folder is the only form that always picks the trial's own `calibration/`. Subprocess also gives cancel and crash isolation. |
| 2026-11-12 | Data protection in git | Root `.gitignore` gets a `MOCAP-PATCH` block ignoring videos, session/consent/manifest files and session sub-folders (demo videos re-included). | Rule 7: the fork is public. |
| 2026-11-12 | Session output path | Must be ASCII-only (spaces allowed); validator error otherwise. Camera source folders may be anything. | OpenSim cannot write `.osim` under non-ASCII paths (upstream-notes §8). |
| 2026-11-12 | Subprocess environment | Every stage runs with `PYTHONIOENCODING=utf-8`, `PYTHONUTF8=1`, `MPLBACKEND=Agg`. | Upstream prints non-cp1252 characters (upstream-notes §9) and must never open figure windows. |
| 2026-11-12 | ffmpeg | `imageio-ffmpeg` (bundled static binary) as fallback when ffmpeg is not on PATH. | Non-experts should not have to install ffmpeg by hand. |
| 2026-11-12 | Video probing | PyAV (already a Pose2Sim dependency) instead of ffprobe: `average_rate` for fps, first decoded frame's `rotation` for the display matrix, packet-timestamp spread (>2 % of intervals off the median) for variable frame rate. | The bundled `imageio-ffmpeg` has no ffprobe; PyAV reads the same metadata without another binary. |
| 2026-11-12 | Normalisation | Hard-link when the source is already constant-rate, upright H.264 in .mp4 (copy if on another drive); otherwise transcode with libx264 CRF 17 `-preset veryfast`, constant frame rate, rotation applied, audio dropped. If trial fps differ by > 0.5, all videos are converted to the most common rate. | Originals are never modified; quality loss of CRF 17 is negligible for 2D pose; audio is not needed. |
| 2026-11-12 | Trial-code check character | Weighted sum mod 31 (alphabet size, prime), weights 1..7. | Catches every single-character typo and every swap of neighbours; Luhn mod N only guarantees that for even N. |
| 2026-11-12 | Trial labels and heights | Labels come from the mapping (the digit for tier 1, else 1..N). Heights and codes are attached to trials in label order; `session new --heights` takes them in that order. | Keeps the participant table and the file mapping in one order the experimenter can check. |
| 2026-11-12 | Extra CLI commands | `mocapapp pick` (choose a calibration video from any folder, D3), `mocapapp map` (manual trial mapping, tier 3), `mocapapp assemble [--dry-run]` (normalise + build trial projects). | Every GUI action needs a CLI equivalent (PROJECT.md §0 rule 3). |
| 2026-11-12 | Thresholds | fps warning below 59 (accepts 59.94); resolution warning when the short side < 1080; cross-camera duration warning > 2 s; tier-2 duration cross-check max(3 s, 10 %). | As specified; 59 so NTSC-style 59.94 fps is not flagged. |
| 2026-11-12 | Intrinsics grading | Pass ≤ 0.6 px (ChArUco) / 0.5 px (chess); warn ≤ 1.0 px; fail above, or < 20 usable frames. Also warn when the detected corners touch < 75 % of a 4x4 image grid or the board tilt varies < 8° (std). A frame counts when ≥ max(8, 30 %) of the ChArUco corners are found. | On the owner's pilot, upstream accepted cam03/cam04 from 4-6 partial frames and produced unusable extrinsics; these checks fail them with concrete advice (verified on the pilot videos). |
| 2026-11-12 | Board detection | Try new and legacy ChArUco layouts, dictionary sizes 50-1000, then the mirrored picture; lock the first variant that works. | OpenCV 5 + calib.io boards (legacy) and mirrored phone video, both met in the pilot. |
| 2026-11-12 | Extrinsic error in cm | `rms_px x mean depth of the clicked points / f`. | Upstream divides by the distance to the world origin, which can be far from the points actually seen. |
| 2026-11-12 | Points behind the camera | A solution with any clicked point at depth ≤ 0 is a **fail**, with an axis-flip suggestion. | Mirrored (left-handed) coordinates fit with 0 px error and the points behind the camera (projection cannot tell the difference). Upstream does not check this. |
| 2026-11-12 | Axis-flip suggestion | Try all sign flips and the X/Y swap; among equally good fits suggest the fewest changes, preferring flip Y, then X, then Z. | For a mirror any single flip fits; +Y on the wrong side is the usual mistake. |
| 2026-11-12 | Clicking without a GUI | `calibrate frame` saves the extrinsic frame as PNG; `calibrate extrinsics --points clicks.csv` takes `label,u,v` (or `hidden`). The GUI click dialog (M4) writes the same data. | Keeps the core headless and testable. |
| 2026-11-12 | Calibration invalidation | New intrinsics delete that camera's extrinsics; changed reference points delete all extrinsics; either deletes `Calib_scene.toml` and its copies in every trial. | A stale calibration in a trial would be used silently by Pose2Sim. |
| 2026-11-12 | `prepare` before calibration | Calibration reads the normalised copies in `inputs/` (upright, constant fps), the same orientation the trials have. | A rotated phone video calibrated as stored would not match its upright trial copies. |
| 2026-11-12 | Stage logs | Each stage's combined stdout/stderr goes to `trials/trial_<label>/mocap_logs/<stage>.log`. | The folder name must not contain "calib" (upstream picks the first such folder as the calibration). |
| 2026-11-12 | Stage success | A stage counts as done only when its exit code is 0 **and** its expected outputs exist (kinematics: `.osim`, `.mot`, `.bvh` if ticked, and no "Error during scaling/IK" in the log). Resume re-checks outputs; a re-run stage makes every later stage stale. | Upstream exit codes are not reliable for kinematics (upstream-notes §7). |
| 2026-11-12 | Sync gating | After synchronisation, any camera with correlation < 0.5 (or NaN) or an offset > 5 s stops the trial as "needs sync fix" before triangulation, also on resume. `--accept-sync` continues as is; `--fix-sync` opens upstream's player once, then continues. | A wrong offset silently ruins every later stage. |
| 2026-11-12 | QA thresholds (initial guesses, DECIDE with pilot data) | good / check: reprojection 20 / 40 mm; frames without 2+ cameras 5 / 20 %; IK marker RMS 30 / 50 mm; feet above floor 0.05 / 0.15 m; lowest sync correlation 0.6 / 0.4 (higher is better). Worst metric sets the trial's light; failed or unsynchronised trials are red. | The demo gives 18.9 mm, 22.5 mm and 0.66; thresholds are printed in every report so readers can judge. |
| 2026-11-12 | Export naming | `<trial code>_trial<label>_<content>.<ext>` (e.g. `PA26-7KQ2M9X_trial1_joint_angles.mot`), plus `README.txt` and `manifest.json` (versions, settings, SHA-256 per file, QA lights, citation). Defaults: config, filtered+LSTM `.trc`/`.c3d`, `.osim`, `.mot`; BVH unticked. A BVH is structure-checked against its `.mot` before export. | Self-explanatory files that carry the pseudonym and never a name. |
| 2026-11-12 | Cancel | Each stage runs in its own process group; cancel kills the whole tree (`taskkill /T` on Windows) and leaves the trial "cancelled", resumable from that stage. | Pose estimation starts worker processes. |
| 2026-11-12 | GUI structure | `gui/main_window.py` holds the step bar and navigation; one module per step in `gui/pages/`, two dialogs (`scene_dialog.py`, `extrinsic_dialog.py`). Pages call `core` only; logic the CLI also needs lives in `core/workflow.py`. A step is reachable once every earlier step is complete or does not apply. | PROJECT.md §0 rule 3: the GUI is a thin wrapper. |
| 2026-11-12 | Background work in the GUI | `gui.common.Background` runs a core function in a `QThread`; results come back through slots of an object in the GUI thread. The window is locked (`busy`) while it runs. | A plain Python callback connected to a worker signal runs in the worker thread and crashed when touching widgets (found by the GUI test). |
| 2026-11-12 | Prepared-copy stamps | Each file in `inputs/` has a `.source` stamp (source path, size, mtime, target fps). A different source is prepared again; choosing another calibration video or remapping a trial also removes the old copy and anything computed from it. | `prepare` used to skip any existing file, so a corrected mapping would have kept the wrong video silently. |
| 2026-11-12 | Sample data | "Try with sample data" / `mocapapp sample` copies `Demo_SinglePerson` (4 cameras, 1 trial, 1.72 m) and converts its Qualisys calibration with upstream's converter. The session is marked `calibration_source = "imported"`; the Videos and calibration steps are skipped for it only. | The demo has no intrinsic/extrinsic videos; it still checks the install and the whole run/QA/export path. |
| 2026-11-12 | Board PDF | ChArUco, new (non-legacy) layout, `DICT_4X4_50`, markers 0.75 of a square, landscape A4 (A3 if needed), 5 cm scale bar; chessboard as alternative. The rendered board is checked by the app's own detector in the tests. | Matches `corners_nb`/`square_size` from the session settings (FR-3.5); the detector also accepts the legacy layout and larger dictionaries. |
| 2026-11-12 | Consent template | `resources/consent_template.md` (English, marked TEMPLATE, placeholders in red), rendered with reportlab into a fillable PDF: trial code (pre-filled), height, consent and optional raw-storage checkboxes, name, date, signature line. No mass, no e-mail. | §8.2; the owner reviews the text, which is plain Markdown so it can be edited without code. |
| 2026-11-12 | Texts | Tutorial (8 pages, `resources/tutorial.md`) and longer UI texts (`resources/strings.toml`) live outside the code. | English only, but translatable later (§7). |
| 2026-11-12 | Run-time settings in the GUI | Pose detection mode, smoothing cut-off, kinematics source and BVH are under "Advanced" on the Run step; they are locked once a stage has finished unless "Start over" is ticked. Run rebuilds each trial's Config.toml first. | Changing settings under finished stages would mix results from two configurations. |
| 2026-11-12 | Consent records | `trials/trial_<label>/consent.json` is written by every `save_session` once the trial folder exists: the §8.3 fields plus `delete_raw` and `retention_until`. `retention_until = "analysis finished"` is set automatically when storage was consented and deletion is not ticked. | One source of truth (session.json) with the per-trial record always in step; dry runs still write nothing. |
| 2026-11-12 | Deletion groups | (a) working copies: `inputs/camNN/trial_<label>.mp4` (+ stamp), `trials/trial_<label>/videos/`; (b) derived: the whole `pose/` folder (2D JSON, overlay videos/images) and `*_json`/`*_img` folders and videos/images in `pose-sync/` and `pose-associated/` except the `sync_*.png` correlation plots; (c) originals: the trial's files in the camera folders. (a)+(b) always go together (D14). | Sync plots and logs contain no picture of the person; 3D results are kept as the owner specified. |
| 2026-11-12 | Deletion confirmation | Every deletion is a plan first (paths, sizes, groups) and then `execute`. Originals (c) need the trial code typed; "Delete all participant data" always needs the trial code; the whole session needs its folder name. CLI commands are dry runs unless `--yes`. Real delete (`unlink`/`rmtree`, read-only files made writable), never the Recycle Bin. | §8.4 safeguards 2-3; scriptable without being easy to trigger by accident. |
| 2026-11-12 | Planned vs on-request deletion | The setup checkbox deletion (Results page, `--after-run`) is refused until every stage is done, the filtered `.trc` and `.mot` parse, and the trial's files are in `export/manifest.json`. A deletion on request (participant asks, later decision) is allowed any time, with a warning when results are incomplete. | §8.4 safeguard 1 applies to deletion triggered by a run; D8 requires deletion at any time. |
| 2026-11-12 | After a deletion | The trial records `raw_deleted_at` (or `withdrawn_at`); the session is then frozen: no re-validation, re-mapping or re-preparing (plain-language error), and the runner skips such trials (a finished one stays done). Withdrawal deletes the trial folder, its QA files and exports, removes them from the export manifest, clears the height and rebuilds the QA report. | Re-preparing would silently copy deleted footage back from the originals; validation counts would no longer match. |
| 2026-11-12 | Deletion log | `manifest.json` in the session root (and appended to `export/manifest.json` if it exists): time, scope, trial, code, item and byte counts per group, session-relative paths; originals only as the list of cameras. | §8.4 item 7: no personal data, and original paths can contain names. |
| 2026-11-12 | Whole-session deletion | Refused while the session folder holds anything the app did not create (hidden files excepted). Calibration originals are never deleted. The sample session never lists "originals" (they are the app's demo videos). | Guards against deleting an unrelated folder chosen as session by mistake. |
| 2026-11-12 | Reminders | Recent-sessions menu marks sessions with footage kept under consent or marked for deletion but not yet deleted; the participant-data dialog and `mocapapp reminders` show the details. Nothing is deleted automatically. | §8.4 item 6. |
| 2026-11-12 | Packaging (DECIDE §9) | Thin bootstrappers instead of a frozen bundle: `install.ps1` (wrapped in a per-user Inno Setup `mocapapp-setup.exe`) and `Install mocapapp.command` download a pinned uv (SHA-256 checked), the tagged source, a managed Python 3.12 and `uv sync --frozen`, then the pose models; shortcuts / `~/Applications/mocapapp.app` start `mocapapp-gui`. Private folder, no admin rights, re-run = repair/update. | OpenSim + ONNX Runtime + PySide6 are fragile under PyInstaller; the lockfile already pins every version for both OSes. Tested end to end on Windows 11 from a checkout. |
| 2026-11-12 | macOS minimum | macOS 15 (Sequoia); the installer refuses older versions with a plain message. | OpenSim 4.6's macOS wheels are `macosx_15_0_universal2`. |
| 2026-11-12 | Installer progress window | The setup .exe runs the bootstrapper in a visible PowerShell window with numbered steps and plain-language failure advice (log in `install.log`); the user never types a command. | A custom GUI progress page in Inno Setup would add code that is hard to test; the window is shown only during installation. |
| 2026-11-12 | Model download (FR-1.2) | `core/models.py` fetches the balanced RTMPose/YOLOX models through rtmlib's own downloader into rtmlib's cache (so Pose2Sim finds them offline). Installer step 4, `mocapapp models --download`, and a first-start offer in the GUI (once per version; Help > Download pose models). Resume is per model: finished models are kept. | Same files, same cache, mirror fallback included; no second download path to maintain. |
| 2026-11-12 | First start (FR-1.1) | The GUI runs the environment checks before the greeting; failures are listed with their fixes, never a traceback. | Non-experts must see what to do. |
| 2026-11-12 | Diagnostics (§9 Logging) | Help > Copy diagnostics / `mocapapp diagnostics`: versions and checks with the home folder and user name replaced; nothing about sessions. | Safe to paste into a public issue. |
| 2026-11-12 | User guide | `resources/user-guide.md`, packaged and shown in-app (Help > User guide). | Installed copies always have the guide that matches their version. |
| 2026-11-12 | Release pipeline | Workflow `mocapapp.yml`: tests on windows-latest and macos-15 for app branches; a `mocapapp-v*` tag also builds both installers into a draft pre-release. Installers are unsigned (SmartScreen/Gatekeeper steps in the guide). | $0 spend; signing certificates cost money and can be added later. |
| 2026-11-12 | Version | 0.1.0rc1; the installers' default ref is the tag of the same version (checked by a test). | An installer always installs the release it was built for. |
| 2026-11-12 | Pose2Sim version in installs | The installers set `SETUPTOOLS_SCM_PRETEND_VERSION_FOR_POSE2SIM=0.10.48+mocapapp` when the source has no `.git` folder (the GitHub source zip). 0.1.0rc1 failed to install from its tag for this reason; fixed in 0.1.0rc2. | Pose2Sim takes its version from git tags (setuptools-scm), which a source zip does not contain. 0.10.48 is the upstream release the fork is based on; `+mocapapp` marks the fork. |
| 2026-11-12 | Release candidate 3 | 0.1.0rc3 replaces rc2, whose macOS zip job got no GitHub runner (capacity). rc3 also has the CLI note for imported sessions and the uninstaller's empty-folder removal. The macOS zip is now built on Linux. | Only the tests need macOS. Zipping on Linux keeps the executable bit and does not depend on scarce macOS runners. |
| 2026-11-14 | Setup without RedirectionGuard (0.1.0rc4) | `mocapapp.iss` sets `RedirectionGuard=no`. The tag's CI now also installs the built setup silently, runs `doctor`, and uninstalls, before building the release setup. | The rc3 setup failed at step 3 on Windows 11 with "untrusted mount point" (os error 448). Inno Setup 6.7+ enables Windows' RedirectionGuard and passes it to install.ps1, and RedirectionGuard refuses the junction uv makes for its Python (`cpython-3.12-...` -> `cpython-3.12.x-...`). The setup runs without admin rights and writes only into the user's folder, so the mitigation protects nothing here. Running install.ps1 directly, as all earlier tests did, never hit this. The CI runner's account is an administrator, and RedirectionGuard trusts junctions made by administrators, so the CI test cannot reproduce this particular failure; it guards against other setup-only problems. |
| 2026-11-14 | Installer independent of the calling shell (0.1.0rc5) | install.ps1 resets `PSModulePath` to Windows PowerShell's own, and uses .NET for the SHA-256 check and for unzipping. The setup test is its own CI job on every push and reports failures as annotations. | rc4's CI setup test, started from PowerShell 7, failed at step 1: Windows PowerShell inherited pwsh's module path and could not load `Get-FileHash`. Users who start the setup from a PowerShell 7 terminal would hit the same error. rc4 was therefore never released. GitHub job logs need a sign-in, annotations do not. |
| 2026-11-14 | Smoothing cut-off and changed settings (0.1.0rc6) | Preflight rejects a Butterworth cut-off at or above half the trial's frame rate, and a filtering failure with "critical frequencies" is explained in plain words. Advanced settings stay editable after a run: `run_state.stage_settings` records the settings each stage ran with, and Run repeats a stage whose settings changed, together with every later stage. They lock only after raw footage was deleted. | The owner's first real session failed in smoothing: 15 Hz cut-off on 30 fps video (Butterworth needs cut-off < fps/2). The fix then required 'Start over', which repeats pose estimation, the slowest stage. Sessions made before rc6 have no record and count as current, so they are not re-run. |
| 2026-11-14 | Owner's usability changes (0.1.0rc7) | Choosing a camera folder named `camNN` fills the other empty camera rows with its sibling `camNN` folders. The Videos page shows the space needed and free instead of asking in dialogs. A BVH file is always made. Advanced settings add the keypoint set (Body with feet, Whole body with wrists, Whole body) and the OpenSim body model (full or simple). The consent form is renamed "Participation consent form"; its blanks (`____`) become fillable PDF fields, and the template note, "Your rights", height and version footer are removed. | Owner's review after the first real session. Changing the keypoint set re-runs every stage; changing the body model re-runs only the joint angles. Sessions from earlier versions keep their recorded settings and are not re-run. Whole-body models (about 210 MB) are downloaded on first use; preflight warns when they are missing. |
| 2026-11-14 | Finished! and "pseudonym" (0.1.0rc8) | On the Results step, **Next** becomes **Finished!**, enabled after an export: it saves, shows the raw-footage reminders if any, and returns to step 1. Everything the user reads says "pseudonym" instead of "trial code" (`mocapapp pdf consent --pseudonym`; `--code` still works). Raw footage kept with consent is now kept until the "study finished", as on the consent form. | Owner's request. session.json, consent.json and the manifests keep the field name `code`, so earlier sessions and exports still load; sessions saved before keep their old "analysis finished" text. |
| 2026-11-15 | Participants with several trials, consent dialog (0.1.0rc9) | session.json gets `participants` (pseudonym, height, consent, deletion choice, withdrawal) and `trials_per_participant`; each trial names its participant. The Session step creates participants (Add/Remove participant, also after creation while they have no videos) and N trials each; the Videos step's mapping gets a Participant column when N > 1. Generate opens a dialog for the study details (study name, purpose, researchers with contact, place of storage, access, usage, retention, risks, compensation), saved as `study_info` and pre-filled into every form of the session. The form drops the data controller and the separate contact field (each researcher has a contact); 'Benefits or compensation' becomes 'Compensation'. 'Participant data and deletion' is only on the Results step and in the File menu. Withdrawal deletes every trial of the participant. | Owner's workflow: create the participant list, print the forms, record, then map trials to participants and cameras. Sessions from earlier versions load as one participant per trial. A trial already processed cannot move to another participant (its results used that person's height). |
| 2026-11-16 | Consent form as a plain printed document (0.1.0rc10) | The consent PDF has no form fields: the study details from the dialog are printed as wrapped text; a detail left blank gets lines to write on; the tick boxes, name, date and signature are printed for filling in by hand. | rc9 pre-filled form fields, which do not wrap: long text (a purpose of one sentence) was cut off when printed. The form is printed and signed on paper anyway. |
| 2026-11-16 | Generate all consent forms (0.1.0rc10) | The Session step's participants table has **Generate all consent forms ...**: the study-details dialog once, then one PDF with a form per active participant, each starting on a new page (`mocapapp pdf consent --session S --all`). The table's headers wrap onto two lines so the table fits without scrolling sideways. | Owner's request: print every form at once. A narrow window scrolled the table and cut off the pseudonyms. |
| 2026-11-18 | Editable pseudonyms (0.1.0rc11) | Every participant still gets a random pseudonym, but the Session step's table lets the researcher type another one or draw a new random one (arrow button; `mocapapp session pseudonym --set/--random`). Allowed: 1-24 letters, digits, `-`, `_`, unique in the output folder (case-insensitive). Locked once signed consent is ticked or any of the participant's trials has results, since the paper form, exports and deletion log refer to it. | Owner request: researchers want their own participant IDs (e.g. P01) or to redraw an awkward code. Free text would invite real names, so the format excludes spaces and the tooltip says not to use names. |
| 2026-11-18 | Project files (0.1.0rc12) | **File > Save project** (Ctrl+S) / **Save project as ...** write a `.mocapproj` JSON file: the session folder (relative to the file and absolute) and the current step; closing the app updates the step. **File > Open project ...** (Ctrl+O) reopens the session at that step when it is still reachable, else at the first unfinished step. `mocapapp project save/show`, `mocapapp gui --project`. | Owner request: save and load projects at their current status. The session folder already holds everything and saves after each change, so the project file is a bookmark, not a copy: no second copy of participant data, nothing to keep in sync. The relative path lets both be moved together; the absolute path lets the file be moved alone. Double-click association in the installers is left for later. |
| 2026-11-18 | Viewer step (0.1.0rc12) | A step 8 after Results: a 3D skeleton of the chosen trial and marker file (play, scrub, rotate, zoom; QPainter, orthographic, floor grid) and a Data tab: joint angles (.mot) or marker positions (.trc) as a plot (matplotlib, with zoom/pan/save), a frame-by-frame table, min/max/range/peak speed per column, 'Compare all trials' overlay, 'Plot speed' and CSV. Reads the trial folders, so no export is needed (Results no longer gates the next step); a finished session still reopens on Results. Same data on the command line: `mocapapp data`. | Owner request: see the output as 3D or as data in the app, e.g. arm joint angles compared between trials. The QA HTML preview stays for a quick check. matplotlib was already installed with Pose2Sim and is now a declared dependency; the 3D view uses plain Qt drawing to stay fast and need nothing new. |
| 2026-11-19 | Double-click project files (0.1.0rc12) | `install.ps1` registers `.mocapproj` per user (`HKCU\Software\Classes\mocapapp.project`, icon and `"mocapapp-gui.exe" "%1"`); `uninstall.ps1` removes it (and `.mocapproj` only while it still points to mocapapp); the Inno setup sets `ChangesAssociations`. macOS is left out for now. | Owner request. The GUI already opened a path given on its command line, so only the registration was missing. Per user keeps the no-admin install; doing it in `install.ps1` rather than in Inno keeps the setup.exe and the script-only install the same. Each double-click starts its own window. |
| 2026-11-19 | Change the output folder later (0.1.0rc12) | **Change output folder ...** on the Session step and **File > Move session to another output folder ...** (`mocapapp session move --to`, `--dry-run`) move the session folder into another output folder, in the background. Same drive: rename. Another drive: copy, compare every file's size, then remove the old folder; a failed copy is removed and nothing changes; a failed removal is reported because the old folder still holds participant data. Refused: non-ASCII path, the same folder, inside the session, an existing folder of that name, or pseudonyms already used in the new folder. The open project file and the recent-sessions list follow. | Owner request. Nothing inside a session folder refers to where it is (the trial folders and session.json use relative paths; the camera folders are outside), so moving the whole folder is enough and keeps one copy of the participant data. |
| 2026-11-19 | Less disk space (0.1.0rc13) | Overlay videos are off by default (`Settings.save_overlay`, `pose.save_video = "none"`). When a trial finishes, its 2D keypoint folders (pose, pose-sync, pose-associated) are removed unless `Settings.keep_keypoints`; `run_state.keypoints_removed` records it, so a resume treats those stages as done, later 3D stages re-run without them, and lost 3D results restart from pose estimation. Before a run, `preflight` warns when the estimated working files exceed the free space (`runner.space_needed`). | Owner's P&A pilot: two cameras, 4-5 min at 60 fps per trial filled the drive (about 60 GB per 9 trials: 42 GB keypoint files, 10 GB overlays, 8 GB videos) and stopped trial 9 with 'No space left on device'. The keypoint files were large because the tracker kept up to 53 lost-person entries per frame for one participant. Nothing after the 3D stages reads them, and removing them also removes derived material that traces the person. The estimate uses the worst case seen and only warns, since it can be far off. |
| 2026-11-19 | Participant details per trial (0.1.0rc13) | `Session.details` lists the details asked (built in: height on by default, weight, handedness, age, sex; custom: number with unit, choice, or text up to 80 characters). Values live in `Trial.details` as normalised text; `Trial.height_m` reads the trial's height, else the participant's. Entering a value fills the same participant's other trials that are still empty; a new or re-assigned trial copies the participant's earliest trial.
